6  ChIP peak data set comparison

6.1 ChIP peak annotation comparision

The plotAnnoBar and plotDistToTSS can also accept input of a named list of annotated peaks (output of annotateSeq).

peakAnnoList <- lapply(files, annotateSeq, TxDb=txdb,
                       tssRegion=c(-3000, 3000), verbose=FALSE)

We can use plotAnnoBar to comparing their genomic annotation.

plotAnnoBar(peakAnnoList)

R function plotDistToTSS can use to comparing distance to TSS profiles among ChIPseq data.

plotDistToTSS(peakAnnoList)

6.2 Functional profiles comparison

As shown in section 4, the annotated genes can analyzed by r Biocpkg("clusterProfiler")(Yu et al. 2012), r Biocpkg("DOSE")(Yu et al. 2015), meshes and r Biocpkg("ReactomePA") for Gene Ontology, KEGG, Disease Ontology, MeSH and Reactome Pathway enrichment analysis.

The clusterProfiler(Yu et al. 2012) package provides compareCluster function for comparing biological themes among gene clusters, and can be easily adopted to compare different ChIP peak experiments.

genes <- lapply(peakAnnoList, function(i) as.data.frame(i)$geneId)
names(genes) <- sub("_", "\n", names(genes))
compKEGG <- compareCluster(geneCluster   = genes,
                           fun           = "enrichKEGG",
                           pvalueCutoff  = 0.05,
                           pAdjustMethod = "BH")
dotplot(compKEGG, showCategory = 15, title = "KEGG Pathway Enrichment Analysis")

6.3 Overlap of peaks and annotated genes

User may want to compare the overlap peaks of replicate experiments or from different experiments. epiSeeker provides readPeakFile that can read a peak file and store it in a GRanges object. Several files can be read simultaneously using lapply, and then passed to vennplot to calculate their overlap and draw venn plot.

vennplot accept a list of object, can be a list of GRanges or a list of vector. Here, I will demonstrate using vennplot to visualize the overlap of the nearest genes stored in peakAnnoList.

genes <- lapply(peakAnnoList, function(i) as.data.frame(i)$geneId)
vennplot(genes)

7 Statistical testing of ChIP seq overlap

Overlap is very important, if two ChIP experiment by two different proteins overlap in a large fraction of their peaks, they may cooperative in regulation. Calculating the overlap is only touch the surface. epiSeeker implemented statistical methods to measure the significance of the overlap.

7.1 Shuffle genome coordination

p <- GRanges(seqnames=c("chr1", "chr3"),
             ranges=IRanges(start=c(1, 100), end=c(50, 130)))
shuffle(p, TxDb=txdb)

7.2 Peak overlap enrichment analysis

With the ease of this shuffle method, we can generate thousands of random ChIP data and calculate the background null distribution of the overlap among ChIP data sets.

Parameter queryPeak is the query ChIP data, while targetPeak is bed file name or a vector of bed file names from comparison; nShuffle is the number to shuffle the peaks in targetPeak. To speed up the compilation of this vignettes, we only set nShuffle to 50 as an example for only demonstration. User should set the number to 1000 or above for more robust result. Parameter chainFile are chain file name for mapping the targetPeak to the genome version consistent with queryPeak when their genome version are different. This creat the possibility of comparison among different genome version and cross species.

In the output, qSample is the name of queryPeak and qLen is the the number of peaks in queryPeak. N_OL is the number of overlap between queryPeak and targetPeak.

7.2.1 The permutation test is one-sided

enrichPeakOverlap() shuffles the target peaks and asks how surprising the observed overlap is. The observed quantity is therefore the fraction of target peaks covered by query peaks (_N\_OL_/_tLen_), and the test answers “are the query peaks enriched within the target peaks?”.

This has two consequences that are worth knowing before comparing two directions:

  • N_OL is direction free, it reports the same number when queryPeak and targetPeak are exchanged, while the p-value is not, because it normalises by the size of the target set and shuffles it. When the two peak sets differ in size, the p-values of the two directions can differ considerably.
  • Even for peak sets of the same size the two null distributions are sampled independently, so repeated runs differ slightly. Use set.seed() together with a large nShuffle when the exact value matters, or compare N_OL if a direction-free measure is what you need.
TipDirection-free p-values with symmetric = TRUE

Parameter symmetric (default FALSE) computes the mirrored direction as well – query and target exchanged – and combines the two one-sided p-values as min(1, 2*min(p, p_rev)). The result then no longer depends on the order of the arguments.

enrichPeakOverlap(queryPeak  = files[[5]],
                  targetPeak = unlist(files[1:4]),
                  TxDb       = txdb,
                  nShuffle   = 1000,
                  symmetric  = TRUE,
                  verbose    = FALSE)

Two things to keep in mind: the number of permutations is doubled, and because the two p-values are combined, the smallest reportable p-value becomes 2/(nShuffle+1).

enrichAnnoOverlap(), which compares the annotated genes of two data sets, uses a hypergeometric test that is already exactly symmetric and therefore has no symmetric parameter. In that function N_OL counts genes rather than peaks, so it can be larger than the number of input peaks: every peak is annotated to its nearest gene and a peak region may overlap several genes.
